# Релиз версии $ARGUMENTS

Запускает только человек. Если версия не передана — спроси её и остановись.

1. `git status --short` и `git branch --show-current` — рабочее дерево должно быть чистым,
   текущая ветка — `feat/*` или `fix/*` согласно AGENTS.md. На `main`, в detached HEAD
   или при чужих незакоммиченных правках остановись и сообщи причину; сам их не убирай.
   Проверь, что тег `v<версия>` ещё не существует; существующий тег не перемещай.
2. Полная проверка, все три должны быть зелёными:
   ```
   make lint && make test && npm run test:e2e
   ```
   Если что-то упало — релиз отменяется, покажи ошибку.
3. Подними версию в двух местах (одинаково):
   - `src/app/app.h` → `#define APP_VERSION "<версия>"`;
   - `package.json` → `"version"`.
   Lock-файлы не меняй; `npm version` не запускай. Если нужна их синхронизация,
   передай это человеку согласно AGENTS.md.
4. Пересобери `make wasm`, проверь `make test T=app` (экран «Об устройстве» читает версию).
5. Допиши запись в `docs/memory.md`: что вошло в релиз (по `git log` с прошлого тега;
   если тегов ещё нет — по текущей истории). Обнови соответствующий пункт `docs/plan.md`.
6. Проверь `git diff --check` и diff. Добавь только файлы подготовки релиза и создай
   коммит в текущей рабочей ветке:
   ```
   git add src/app/app.h package.json docs/memory.md docs/plan.md
   git commit -m "chore(release): подготовка v<версия>"
   ```
7. Покажи итог проверок и коммит. Слияние проверенной рабочей ветки в `main`, создание
   тега `v<версия>` на итоговом коммите `main` и публикацию выполняет человек.
   Агент не переключается на `main`, не сливает ветки и не создаёт тег в рабочей ветке.
   После слияния предложи человеку команды для выполнения:
   ```
   git tag v<версия>
   git push origin main
   git push origin v<версия>
   ```
   Перед тегом человек проверяет, что находится на нужном коммите `main`.
   Правило ask/prompt для push не отменяет требование AGENTS.md «только человек».
