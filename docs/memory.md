# Журнал проекта

Формат записи: дата, кто (агент/модель), **Сделано / Решения / Дальше / Ловушки**.
Новые записи — в конец файла. Hook `SessionStart` показывает агенту последнюю запись.

## 2026-10-12 — Claude (каркас проекта)

**Сделано**
- C-ядро без libc: `gfx` (раскладка SSD1309), `fonts` (5×7, RU/EN), `menu`, `app`.
- Экраны: главное меню, Показания (имитация датчиков), Настройки (автосон, яркость, язык,
  инверсия, сброс), Символы (таблица шрифта, 2 страницы), Об устройстве.
- HAL: `display.h` с тремя реализациями — плата (`hal/ssd1309`), браузер (`hal/web`), тесты.
- Эмулятор `web/`: canvas 128×64 ×5, кнопки ▲▼ OK ◄ и клавиатура, выбор цвета OLED.
- Тесты: 38 unit (`make test`), 5 e2e (`npm run test:e2e`). Всё зелёное.
- Обвязка: AGENTS.md, `.claude/` (rules, skills, settings, hooks), `.codex/`, `.mcp.json`.

**Решения**
- WebAssembly собирается обычным `clang --target=wasm32` без Emscripten: ядру не нужна
  libc, итоговый `emu.wasm` ~12 КБ. Это же гарантирует, что код переносится на МК.
- «RAM дисплея» в эмуляторе обновляется только по `display_flush()` — как у SSD1309.
- Датчики детерминированные (функция от времени), e2e открывает `?paused=1` и двигает время
  через `window.emu.tick(ms)` — тесты не флакуют.
- Единый источник инструкций — `.claude/`; для Codex `npm run sync:agents` раскладывает
  навыки в `.agents/skills/` и правила во вложенные `src/AGENTS.md`, `web/AGENTS.md`.

**Дальше**
- Сделать скриншоты для `docs/about.md` (см. открытые пункты `docs/plan.md`).
- Этап 2: экран «График» — первый кандидат.

**Ловушки**
- `strings.h` как имя модуля конфликтует с системным `<strings.h>` — модуль назван `i18n`.
- clang под wasm32 может сам вставить вызов `memset` — для этого есть `hal/web/libc_shim.c`,
  а сборка идёт с `-ffreestanding`.
- Шрифт-данные генерируются: правка `font5x7_data.c` руками заблокирована hook-ом.
- Подписи пунктов меню длиннее 13 символов наезжают на значение справа.

## 2026-10-12 — Codex (локальный запуск под Windows)

**Сделано**
- Собран `web/build/emu.wasm`, сервер запущен через `npm run serve` на порту 8080.
- В браузере проверен переход «Главное меню» → «Показания» → «Главное меню»;
  `data-ready=true`, ошибок и предупреждений в консоли рабочей страницы нет.
- Скриншот: `docs/screenshots/local-launch.png`. Повторная сборка и запуск:
  `./build/run-local.ps1` (локальный скрипт в игнорируемом каталоге).

**Решения**
- В окружении есть Node.js 22.23.3, но нет make/clang/gcc в PATH и готового wasm.
- В `build/tools` скачан переносимый Zig 0.14.1 с официального ziglang.org;
  `zig cc -target wasm32-freestanding` собирает C-ядро с предупреждениями и `-Werror`
  из Makefile. npm-зависимости для статического сервера не нужны.
- Исходники приложения и lock-файл не менялись; полный lint/unit/e2e не запускался.

**Дальше**
- Для стандартных команд разработки подготовить make, clang/lld, gcc и clang-format.
- Исправить обработку корневого URL в сервере для Windows отдельной задачей.

**Ловушки**
- На Windows `normalize('/')` возвращает обратный слеш: проверка `endsWith('/')`
  в `scripts/serve.mjs` не добавляет index.html, поэтому `/` отвечает 404.
  Рабочий адрес: `http://localhost:8080/index.html`.
- Кэш Zig направлен в `build/`, чтобы не требовалась запись вне проекта.
